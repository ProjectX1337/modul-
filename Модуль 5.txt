1. Функциональное назначение
Разработанное программное обеспечение представляет собой настольное приложение, предназначенное для разграничения прав доступа сотрудников на основе ролей.

Приложение выполняет следующие функции:

аутентификация пользователей по логину и паролю;

защита от автоматического подбора паролей с помощью интерактивной капчи (сборка пазла 2х2);

блокировка учетной записи при трехкратном подряд неудачном вводе данных;

разграничение доступа к интерфейсу в зависимости от роли («Администратор» или «Пользователь»);

ведение базы данных пользователей с возможностью добавления новых записей и снятия блокировки (доступно только администратору).

2. Структура проекта
Код приложения разделен на отдельные модули для удобства поддержки (согласно принципам объектно-ориентированного программирования):

main.py — точка входа. Запускает приложение и инициализирует базу данных.

database.py — модуль для работы с СУБД SQLite.

captcha.py — пользовательский виджет для реализации пазла.

login_window.py — главное окно авторизации.

admin_window.py — интерфейс администратора (таблица пользователей и управление).

user_window.py — интерфейс обычного пользователя.

Графические файлы piece1.png - piece4.png — фрагменты изображения для капчи.

3. Описание базы данных
Для хранения данных используется встроенная база данных SQLite (файл app_database.db). При первом запуске программы создается таблица users со следующими полями:

id (INTEGER) — первичный ключ, автоинкремент;

login (TEXT) — уникальный логин пользователя (ограничение UNIQUE);

password (TEXT) — пароль;

role (TEXT) — роль в системе;

is_blocked (INTEGER) — статус блокировки (0 — доступ открыт, 1 — заблокирован);

failed_attempts (INTEGER) — счетчик неудачных попыток входа.

4. Описание методов и параметров
4.1. Класс DatabaseManager (модуль database.py)
Отвечает за все взаимодействие с базой данных.

__init__(self, db_name="app_database.db")

Параметры: db_name — строка с именем файла БД.

Действие: Устанавливает соединение, создает таблицу (если ее нет) и добавляет администратора по умолчанию (admin/admin).

authenticate(self, login, password)

Параметры: login, password (строки).

Возвращает: кортеж с данными пользователя или None, если пароль неверный.

increment_failed_attempts(self, login)

Параметры: login (строка).

Действие: Увеличивает счетчик ошибок на 1. Если счетчик достигает 3, меняет флаг is_blocked на 1 (блокировка).

unblock_user(self, user_id)

Параметры: user_id (целое число).

Действие: Снимает блокировку и сбрасывает счетчик попыток в 0.

add_user(self, login, password, role)

Параметры: login, password, role (строки).

Возвращает: True при успехе, False если логин уже занят (обрабатывается исключение sqlite3.IntegrityError).

4.2. Класс PuzzleCaptcha (модуль captcha.py)
Наследуется от QWidget. Реализует логику капчи.

__init__(self, image_paths, tile_size=100)

Параметры: image_paths (список строк с путями к 4 картинкам), tile_size (размер стороны плитки в пикселях).

Действие: Создает сетку 2х2, масштабирует картинки и перемешивает их.

on_tile_clicked(self, index)

Параметры: index (целое число от 0 до 3).

Действие: Обрабатывает клик мыши. Запоминает выбранную плитку, а при клике на вторую — меняет их местами.

is_solved(self)

Возвращает: True, если список current_order равен [0, 1, 2, 3] (пазл собран верно), иначе False.

reset(self)

Действие: Сбрасывает выделение и перемешивает пазл заново.

4.3. Класс LoginWindow (модуль login_window.py)
Окно входа в систему.

handle_login(self)

Действие: Считывает текст из полей. Проверяет их на пустоту. Вызывает is_solved() у капчи. Если капча не собрана или пароль неверный — вызывает register_failed_attempt(). При успехе выводит сообщение и вызывает open_workspace().

open_workspace(self, user_id, user_login, role)

Параметры: user_id (число), user_login (строка), role (строка).

Действие: Скрывает текущее окно и открывает AdminWindow или UserWindow в зависимости от роли.

4.4. Класс AdminWindow (модуль admin_window.py)
Интерфейс для управления пользователями.

load_users(self)

Действие: Вызывает метод get_all_users() у БД и обновляет содержимое QTableWidget (таблицы на форме).

add_user(self)

Действие: Берет текст из полей ввода. Проверяет, нет ли такого логина в БД (метод login_exists). Если нет — добавляет и обновляет таблицу.

unblock_user(self)

Действие: Получает ID выбранной строки из таблицы и передает его в метод unblock_user базы данных.

5. Обработка ошибок и валидация
В приложении реализована обратная связь с пользователем через диалоговые окна QMessageBox:

При пустых полях выводится предупреждение (иконка Warning).

При неверном пароле или несобранной капче выводится сообщение об ошибке (иконка Critical) и происходит сброс капчи.

При попытке добавить существующий логин выводится сообщение о дубликате.

Если пользователь заблокирован, при попытке входа выводится соответствующее уведомление, и доступ к системе не предоставляется.

Все операции с базой данных обернуты в блоки try-except (в частности, sqlite3.IntegrityError), что предотвращает аварийное завершение программы при некорректных действиях.
